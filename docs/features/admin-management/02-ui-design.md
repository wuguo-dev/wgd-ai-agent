# 全系统视觉与管理员后台交互契约

## 范围与设计依据

本契约覆盖独立管理后台、社区列表与详情、AI 聊天、登录与注册的视觉一致性。管理员业务包含控制台、问题管理、回答管理、用户管理、分类管理与操作日志。实际字段、统计口径、状态规则及排序参数由本目录 API 契约定义。

2026-11-18 审查了 StudentLayout、AuthLayout、ReviewView、CategoryManageView、AdminNav、社区首页、ConversationSidebar、variables.css、community.css 与 auth-form.css，同时读取统一前端架构和社区 API 契约。所有实现复用 Vue 3、Element Plus、现有身份 Store 与请求层。

## 管理后台框架

AdminLayout 使用左侧导航、顶栏和主内容三部分。桌面侧栏保持全高，顶部显示平台品牌与管理身份，下方依次提供控制台、问题管理、回答管理、用户管理、分类管理、操作日志。当前入口同时用背景、字重与 aria-current 表示。折叠时显示可辨识图标并提供 Tooltip 与完整无障碍名称。

顶栏高度 64px，左侧为侧栏切换与面包屑，右侧为账号菜单。面包屑使用当前路由 meta 生成，主内容保留一个清楚的页面 h1。账号菜单展示用户名、管理员身份、返回社区及退出。退出沿用真实接口、Loading 与错误反馈，身份由现有 Store 恢复。

主内容设置 `min-width: 0`，最大宽度 1440px，桌面外边距 24–32px，手机 16px。横向溢出局限于表格容器，顶栏、面包屑和筛选区均可收缩。顶部展示共享会话或网络错误区域，页面数据区域独立显示请求状态。

1024px 及以上使用常驻侧栏，1024px 初始可折叠为 72px。1024px 以下使用左侧 ElDrawer，宽度 `min(280px, 86vw)`。点击导航后关闭 Drawer，Escape 和遮罩支持关闭，关闭后焦点回到菜单按钮。路由变化同步关闭侧栏浮层，避免遮罩残留。折叠状态可仅保存在当前组件内存。

## 控制台

统计数据全部来自统计接口。五项主指标依次展示学生总数、问题总数、回答总数、待审核问题、待审核回答。四项辅助指标展示启用学生、禁用学生、已删除问题、已删除回答。使用一致的 ElCard/Statistic 排版与明确名称，主指标数字更突出，数值与指标名称保持清楚层级。

1920px 与 1366px 五项主指标可在有效宽度允许时排列五列，四项辅助指标排列四列。1024px 使用两至三列，768px 两列。390px 与 375px 主指标采用两列，四项辅助指标、待处理事项和管理入口采用单列。手机主卡保留完整中文标签、数字与查看入口，第五项主指标在末行左侧，沿用相同卡片尺寸。待审核与已删除卡片可导航至带相应筛选参数的管理页。统计口径由页面一处简短说明表达，具体规则以 API 契约为准。加载使用骨架，失败显示“—”与重试入口，成功的零值显示 0。刷新期间按钮显示 Loading 状态。

## 管理列表共同结构

各列表包含页面标题、筛选面板、结果表格、分页与详情。使用 ElForm 和可见 Label，查询与重置按钮位于筛选区域末尾。桌面筛选网格四列，1024px 两列，手机单列。筛选变化先由“查询”或 Enter 提交，重置恢复该页面定义的默认条件并回到第一页。当前查询条件建议同步 URL，前进、后退和刷新后能够恢复。

| 页面 | 筛选字段 | 表格重点列 |
| --- | --- | --- |
| 问题管理 | 标题、作者、分类、审核状态、删除状态、契约支持的排序 | 标题、作者、分类、审核状态、删除状态、发布时间、操作 |
| 回答管理 | 所属问题、作者、审核状态、删除状态、契约支持的排序 | 问题标题、回答摘要、作者、审核状态、删除状态、提交时间、操作 |
| 用户管理 | 用户名、角色、账号状态 | ID、用户名、角色、状态、注册时间、详情/启用/禁用 |
| 分类管理 | 沿用既有名称、排序、状态及管理操作 | 名称、说明、排序、状态、编辑/启停 |
| 操作日志 | 管理员、操作类型、开始与结束时间 | 管理员、操作、目标类型与ID、时间、详情 |

表格使用合理列宽，长内容最多两行摘要，通过详情读取完整文本。操作列提供“查看”和当前允许的状态操作，较多操作可使用带明确标签的 Dropdown。审核操作使用主色或中性按钮，删除使用 danger，恢复使用清楚的文字动作。ADMIN 用户行提供可读详情与受保护说明，用户状态操作仅在 STUDENT 行显示。

ElPagination 与列表同步真实 total，小屏使用 prev/pager/next 及精简页码。筛选、排序变化重置页码，最后一条记录移除后回退至有效页码。请求使用现有 generation 或取消机制，迟到响应不能覆盖新条件结果。

## 详情与操作弹窗

问题、回答、用户及日志详情采用 ElDialog 或 ElDrawer，宽度 `min(760px, calc(100vw - 32px))`。正文保留换行并允许长词断行，内容区域使用合理 max-height 与独立滚动。可见身份字段仅限公开用户名、用户ID、角色、状态和业务时间。

问题与回答详情展示审核状态、审核原因、删除状态、删除原因、操作者与时间等接口支持的真实字段。回答详情显示对应问题信息及其状态。操作记录通过审计接口读取，必要时链接到预筛选日志列表。操作日志详情显示原因及变更前后状态，并以安全文本方式呈现。

| 操作 | 确认与反馈 |
| --- | --- |
| 审核通过 | 明确目标与“确认通过”，沿用原审核服务 |
| 审核驳回 | 必填原因，限制长度与契约一致，失败保留输入 |
| 删除内容 | 独立危险确认，显示标题/摘要与影响范围，必填删除原因，确认按钮为“确认删除” |
| 恢复内容 | 说明恢复后沿用原审核状态，所属问题状态仍影响回答公开性，确认按钮为“确认恢复” |
| 禁用学生 | 展示用户名与现有会话将被拒绝的影响，二次确认，必要原因按契约提交 |
| 启用学生 | 展示目标，成功后更新列表与打开的详情 |
| 分类停用 | 说明历史内容保留分类、新问题不可再选择，确认后调用现有接口 |

请求期间禁用重复确认并显示 Loading，网络错误及冲突置于当前 Dialog 内。成功响应后关闭确认并刷新当前列表，详情同步新状态。409 显示状态已变化并允许刷新。写请求超时显示结果尚未确认，提示刷新当前记录核对，用户可继续处理确认后的状态。Dialog 关闭后焦点返回触发控件，表单校验失败聚焦首个错误项。

## 学生社区、AI 与认证统一

StudentLayout 与 AdminLayout 共用品牌、字号、按钮、账户反馈和主题变量。社区首页内容区 1200px，桌面使用主问题列表与约 280px 右侧栏，右侧提供发布问题、我的提问/回答/收藏真实入口。标题、分类、作者时间、摘要有清楚层级，搜索与分类围绕真实内容检索。768px 及以下改为单列，将发问操作留在标题区，个人入口回到统一导航。

详情阅读区 880px，标题与作者信息独立成清楚的头部，正文、回答列表和回答输入区形成连续阅读顺序。发布页以正文表单为主区，桌面侧栏说明待审核规则、内容长度及提交后去向，移动端说明合并到提交区域。个人中心桌面使用资料侧栏与记录主区，主区保留现有三个业务页签，手机资料栏自然堆叠。移动端筛选和发布按钮可自然换行，回答与收藏保持明确禁用及请求状态。

AI 页面保留现有会话列表、流式内容、停止、历史持久化和引用交互，使用共享变量调整侧栏、分隔线、按钮、输入框和消息文本。历史栏提供独立标题与新建按钮，空态提供可点击的学习提问卡片，选择后填充输入供用户提交。输入区使用带清楚边框的整体容器，文本框、发送/停止和输入提示有固定层次，长草稿允许输入框内部滚动。聊天主体独立滚动，输入区始终可达，手机历史会话 Drawer 沿用同一浮层规范。长代码仅在代码块内横滚，普通消息自然断行。身份清除与 SSE 错误行为继续沿用既有实现。

登录与注册使用相同品牌、文字、表单间距、卡片圆角和按钮尺寸。桌面延续双栏结构，品牌侧用简明的社区提问交流、AI 问答与历史记录功能说明支撑产品背景，减少占位式装饰。移动端保留品牌和表单。错误紧邻表单并可被辅助技术读取，密码显隐维持现有 44px 可交互区域。管理员复用同一登录入口及有效身份反馈。

## 通用状态与安全呈现

列表首屏加载使用 Skeleton，后续刷新有清楚 Loading 状态。空结果表达“暂无符合条件的记录”，有条件时提供重置筛选。请求失败呈现错误与重试，成功只由真实成功响应触发。401 沿用会话失效回跳，403 保留登录身份并呈现权限说明。

所有用户输入、标题、正文、审核原因、删除原因和日志内容采用文本插值。社区正文使用 `white-space: pre-wrap` 和 `overflow-wrap: anywhere`。AI Markdown 沿用既有关闭原生 HTML 与净化流程。标签使用“待审核/已通过/已驳回”“正常/已删除”“启用/禁用”等明确文字，并配合主题颜色。

图标操作具有 aria-label，侧栏切换提供 aria-expanded，页面支持键盘导航，Dropdown、Dialog 和 Drawer 使用 Element Plus 的焦点管理。交互目标至少 44px，焦点清楚可见。动画尊重 prefers-reduced-motion。

### 本轮补充交互验收条款

1. 同条件重复查询与重置必须触发一次新的数据读取。改条件查询回到第一页，同条件刷新后的数据按当前条件展示，快速连续请求继续使用既有迟到响应隔离。
2. 状态操作后按返回总数检查有效页码，末页最后一条离开当前筛选集时回退到有效页并重新读取。验证问题、回答、用户与收藏等复用列表的正常分页行为。
3. 用户详情加载期间与失败后禁用启用/禁用及其确认入口。失败区域提供明确重试，重试成功后才允许状态操作。切换对象时清空上一对象的确认和错误反馈，迟到详情不能覆盖当前对象。
4. 管理侧栏展开和折叠均可读出“控制台、问题管理、回答管理、用户管理、分类管理、操作日志”的完整名称，返回社区入口名称明确。手机头像按钮可读出账号菜单含义，当前导航使用可感知激活状态，Tab 焦点可见。
5. 列表首屏和重新加载均保留稳定结果区高度。可使用保留行的加载遮罩或有最小高度的骨架容器，加载期间防止操作旧数据。请求失败呈现错误与重试，内容区和分页避免明显上下跳动。
6. 若分类使用本地分页，名称或状态筛选、重置回到第一页，编辑或启停导致当前页超界时回退。筛选后的总数、分页与表格使用同一数据集，继续维持原服务端分类权限和数组接口。
