# 学生社区 UI 与交互规范

## 现有界面审查

2026-11-18 阅读了 StudentLayout、社区落地页、AgentChatView、router、variables.css、global.css 和统一前端架构文档。现有社区仅含欢迎信息和占位卡片。StudentLayout 已提供品牌、社区与 AI 导航、当前身份、退出及定时会话恢复，可直接扩展业务入口。Element Plus 控件采用显式导入，字体沿用 Inter 与中文系统字体。社区页沿用现有主色、边框、卡片及焦点样式。

现有路由在角色不足时清除身份并跳到登录。管理端实施时应呈现权限不足反馈，并保留有效登录身份。导航按角色显示业务入口，后端承担最终权限验证。

## 视觉基础

| 元素 | 规范 |
| --- | --- |
| 主色与悬停 | 复用 `--color-primary` 与 `--color-primary-hover` |
| 画布与卡片 | 复用 `--color-background` 与 `--color-surface` |
| 文本与边框 | 复用 `--color-text`、`--color-muted`、`--color-border` |
| 字体 | 复用 `--font-sans`，正文 15–16px、元信息 13px、标题 26–32px |
| 圆角 | 外层卡片复用 `--radius-card`，输入使用 Element Plus 共享圆角 |
| 间距 | 8、12、16、24、32px，表单项保持 20–24px 垂直间距 |
| 操作区域 | 按钮与可交互导航最小高度 44px |
| 焦点 | 继承全局 focus-visible 外框，键盘可达 |

页面使用 scoped CSS 维护布局。共享主题调整集中于 variables.css。界面仅展示实际业务信息，回答数量仅在接口提供真实值时展示。

## 统一导航与页面结构

统一 Header 提供品牌、学生社区、AI 智能问答、个人中心及当前用户。ADMIN 显示管理入口与管理员身份。Agent 入口沿用其已有角色规则。社区普通页内容最大宽度建议 1100–1200px，阅读区 800–900px，发布表单 760px。保留 Agent 当前全高工作区布局。

| 页面 | 内容与主要操作 |
| --- | --- |
| 社区首页 | 页面标题、发布问题、搜索、分类筛选、问题列表、分页 |
| 发布问题 | 返回社区、标题、启用分类、正文、提交、审核提示 |
| 问题详情 | 返回列表、分类、标题、作者与时间、状态、完整正文、收藏、通过审核的回答、回答表单 |
| 个人中心 | 用户名与角色、我的提问/我的回答/我的收藏、状态、驳回原因、分页 |
| 问题审核 | 管理导航、待审核表格、详情、通过与驳回、分页 |
| 回答审核 | 问题标题、回答作者与内容、详情、通过与驳回、分页 |
| 分类管理 | 分类列表、启停状态、排序、新增、编辑 |

## 首页与检索

列表以标题作为详情链接，正文摘要最多两至三行，分类、作者、发布时间组成次级信息。长标题自然换行，用户名和连续英文允许断行。搜索输入提供可见标签或 aria-label，Enter 与搜索按钮执行同一提交逻辑。搜索及分类变化将页码重置至第一页。清空条件恢复完整列表。请求期间使用 Element Plus Skeleton 或明确加载状态，失败显示错误及重试。空结果提供“暂无符合条件的问题”及清除筛选操作。

分页使用 ElPagination，小屏保留上一页、页码、下一页，页码数量控制为五个。请求响应应绑定当前查询条件，避免迟到请求覆盖新筛选结果。

## 发布、回答与收藏

发布与回答采用 Element Plus Form、Input、Select 和 Button。标题、正文、分类均有可见标签，字数上限以冻结 API 契约为准。必填及长度错误紧邻控件呈现。提交前锁定操作，校验与请求完成后释放，失败保留输入。

成功发布后进入问题详情或我的提问，展示“已提交，等待管理员审核”。回答成功清空输入并显示相同审核提示。公开回答列表始终由服务器返回的已通过数据驱动。未通过问题详情显示作者可见的审核状态与驳回原因，回答及收藏操作依据当前状态禁用并提供可理解的原因。

收藏按钮呈现“收藏问题”或“取消收藏”。请求处理中禁用本按钮并显示 Loading。收到成功响应后更新状态，失败保留原状态并展示错误。写请求超时时展示“操作结果尚未确认，请刷新列表确认后重试”，避免将超时直接解释为数据库写入失败。

## 个人中心

三个区域使用 Tabs 或等效可访问导航，每个区域独立分页。提问和回答均显示“待审核”“已通过”“已驳回”，搭配 ElTag 状态色。审核原因以纯文本完整显示。我的回答提供关联问题标题，问题不可见时仍保留本人回答记录与状态，并由详情请求提供不可见反馈。收藏区域提供问题链接与取消收藏，取消成功后刷新本页，并处理最后一条移除后的页码回退。

## 管理交互

管理列表使用 ElTable 和 ElPagination，列优先级为标题/内容、作者、时间、操作。详情通过 Dialog 展示完整纯文本及上下文，宽度建议 `min(720px, calc(100vw - 32px))`，长正文允许对话框内部垂直滚动。

通过操作使用明确确认，驳回对话框内必须填写原因。审核请求处理中锁定当前操作，成功后刷新待审核列表，失败保留对话框与原因。收到状态冲突时展示“内容已被处理，请刷新列表”，重新读取当前状态。关闭对话框后恢复触发控件焦点。

分类表单包含名称、描述、排序、启停状态，服务端校验失败反馈到页面。停用操作说明历史问题继续显示原分类，新问题发布选择器仅提供启用分类。分类管理不提供物理删除。

## 响应式

| 视口 | 布局行为 |
| --- | --- |
| 1920px | 内容居中，页宽有上限，列表和阅读区保持合理行长 |
| 1366px | 标题与发布按钮同排，搜索与分类可同排 |
| 768px | Header 导航独立换行，分类自然换行，表单保持单列 |
| 390px | 页面左右 16–20px，标题与发布操作允许堆叠，搜索独占一行 |
| 375px | 分页精简，表单控件宽度 100%，按钮可换行，Dialog 留至少 16px 边距 |

列表、标题与正文均设置 `min-width: 0` 及合适断行。页面整体避免水平滚动。管理表格在自身容器横向滚动，外层页面保持视口宽度，提供清楚的完整内容入口。

## 状态、安全与可访问性

每个数据区域均具有加载、成功、空、失败四种状态。403 使用可见权限反馈，401 沿用既有失效回跳，网络错误显示重试入口。成功与失败状态分别使用 role=status 和 role=alert 或 Element Plus 对应反馈，避免重复播报。

问题、回答、标题、用户名与审核原因通过 Vue 文本插值渲染，正文使用 `white-space: pre-wrap` 与 `overflow-wrap: anywhere`。所有表单具有标签，主要操作可由键盘完成，状态由文字和颜色共同表达。业务信息来自当前用户会话与实际接口，页面状态无需进入浏览器持久存储。

## 视觉验收要求

在 1920、1366、768、390、375px 分别检查首页、发布、详情、个人中心及管理列表，记录页面是否溢出、按钮是否可达、表单错误是否可读。至少核对桌面和手机截图。截图复核与真实浏览器结果由 QA 报告记录，本设计文档记录实施规范。
